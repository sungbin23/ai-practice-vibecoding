# PRD 3단계 — 사용자 프로필, 레시피 저장, 대시보드

## 목표
사용자가 로그인해서 마음에 드는 레시피를 [나의 레시피]에 저장하고, 대시보드에서 자신의 요리 통계를 본다.

## 사용자 시나리오
1. 상단 [로그인]에서 회원가입(아이디·비밀번호·닉네임) 또는 로그인한다.
2. 레시피 카드의 [저장]을 누르면 [나의 레시피]에 들어간다. 로그인하지 않았으면 로그인 창을 띄운다.
3. [나의 레시피] 탭에서 저장한 레시피를 펼쳐 보고 삭제할 수 있다.
4. [대시보드] 탭에서 통계를 본다.

## 기능 요구사항
| ID | 내용 |
|----|------|
| F3-1 | 아이디 3~20자(영문 소문자·숫자·_, 대문자로 입력해도 소문자로 통일), 비밀번호 4~100자, 닉네임 1~20자. 아이디 중복 불가. |
| F3-2 | 비밀번호는 `crypto.scrypt` + 사용자별 salt로 해시해 저장한다(평문 저장 금지). |
| F3-1a | 같은 아이디로 로그인을 5번 연속 틀리면 1분 동안 429 "로그인을 너무 많이 실패했어요. 1분 뒤 다시 시도해 주세요." |
| F3-3 | 로그인 시 무작위 세션 토큰을 `HttpOnly; SameSite=Lax` 쿠키로 발급한다. 세션은 서버 메모리에 보관(서버를 다시 켜면 다시 로그인). |
| F3-4 | 사용자는 `data/users.json`, 저장 레시피는 `data/saved_recipes.json`에 저장한다(`data/` 폴더는 git 무시 대상). |
| F3-5 | `GET/POST /api/my-recipes`, `DELETE /api/my-recipes/:id`. 다른 사용자의 레시피는 보거나 지울 수 없다. 같은 제목 레시피는 중복 저장하지 않는다. |
| F3-6 | 로그인한 사용자의 재료 인식·레시피 생성 횟수를 기록한다. |
| F3-7 | `GET /api/dashboard`: 저장 레시피 수, 재료 인식 횟수, 레시피 생성 횟수, 평균 조리 시간, 요리 종류별·난이도별 개수, 자주 쓴 재료 상위 5개. 화면에는 CSS 막대그래프로 그린다. |

## 데모 모드
- 로그인·저장·대시보드는 API 키와 무관하므로 데모 모드에서도 그대로 동작한다. 데모 모드에서 저장한 샘플 레시피도 일반 레시피처럼 저장된다.

## 완료 기준
- 데모 모드에서 회원가입 → 사진 업로드 → 레시피 생성 → 저장 → [나의 레시피]에 표시 → 대시보드 수치가 늘어나는 것을 확인한다.
