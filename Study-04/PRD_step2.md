# PRD 2단계 — 인식된 재료로 레시피 생성

## 목표
1단계에서 인식한 재료를 사용자가 고친 뒤, 요리 종류와 난이도를 골라 `deepseek/deepseek-chat-v3.1:free` 모델로 레시피를 추천받는다.

## 사용자 시나리오
1. 인식 결과가 편집 가능한 재료 칩으로 바뀐다. 잘못 인식된 재료는 ×로 지우고, 빠진 재료는 입력창으로 추가한다.
2. 요리 종류(아무거나·한식·양식·중식·일식)와 난이도(아무거나·쉬움·보통·어려움)를 고른다.
3. [레시피 추천받기]를 누르면 레시피 카드 3개가 나온다.
4. 카드를 펼치면 재료(가진 것/더 필요한 것 구분), 조리 순서, 팁을 볼 수 있다.

## 기능 요구사항
| ID | 내용 |
|----|------|
| F2-1 | 재료 추가·삭제. 빈 문자열·중복(대소문자·공백 무시)은 추가하지 않고 입력칸 바로 아래에 이유를 보여 준다. 재료가 0개면 추천 버튼을 막고 버튼 옆에 "재료를 1개 이상 넣으면 누를 수 있어요"를 보여 준다. [모두 지우기]는 재료가 2개 이상이면 확인을 받는다. |
| F2-2 | 사진 없이 재료를 직접 입력해서도 추천받을 수 있다. |
| F2-3 | 서버 `POST /api/recipes`가 `{ ingredients[], cuisine, difficulty }`를 받는다. 재료는 최대 40개, 각 40자까지만 받는다. |
| F2-4 | 텍스트 모델에 JSON 형식으로 레시피 3개를 요청한다. 레시피 스키마: `{ title, cuisine, difficulty, timeMinutes, servings, ingredients:[{ name, amount, have, pantry }], steps[], tip }`. `pantry`는 소금·설탕·간장 같은 기본 양념(`lib/recipes.js`의 `PANTRY`)이면서 가진 재료가 아닐 때 `true`이며, "더 필요한 재료" 개수와 대시보드 TOP 5에서 빠진다. |
| F2-5 | `have`·`pantry`는 서버가 다시 계산한다(모델 값을 믿지 않음). `have`는 사용자 재료 목록과 비교(포함 관계 허용, 1글자 이름은 정확히 일치할 때만). 화면은 가진 재료를 ✓, 더 필요한 재료를 +, 기본 양념을 회색 글자로 구분한다(색만으로 구분하지 않음). |
| F2-6 | 응답 JSON이 깨지면 "레시피를 만들지 못했어요. 다시 시도해 주세요"를 안내한다. |

## 데모 모드
- API를 호출하지 않고 샘플 레시피 묶음에서 고른 요리 종류·난이도에 맞는 것을 최대 3개 돌려준다. 맞는 것이 없으면 아무 샘플이나 3개를 보여 준다.
- 사용자가 고친 재료 목록으로 `have`를 계산하므로 재료 편집 결과가 화면에 반영된다.

## 완료 기준
- 데모 모드에서 재료 편집 → 종류·난이도 선택 → 레시피 3개 표시, 가진 재료 표시가 편집 내용과 일치한다.
