# PRD 1단계 — 냉장고 사진으로 재료 인식

## 목표
사용자가 냉장고 사진을 올리면 `google/gemma-3-27b-it:free`(OpenRouter) 모델로 사진 속 식재료를 인식해 목록으로 보여 준다.

## 사용자 시나리오
1. 사용자가 사진을 선택하거나(파일 선택·드래그 앤 드롭, 모바일은 카메라 촬영) 화면에 놓는다.
2. 미리보기가 뜨고 [재료 인식하기] 버튼을 누른다.
3. 로딩 표시(몇 초째 기다리는지 함께 표시) 후 인식된 재료가 칩 목록(분류·이름·대략 수량)으로 나온다. 수량이 "알 수 없음"이면 수량은 생략하고, 사용자가 직접 추가한 재료는 분류 없이 이름만 보인다.

## 기능 요구사항
| ID | 내용 |
|----|------|
| F1-1 | JPG·PNG·WEBP 이미지만 받는다. 다른 형식이면 안내 메시지를 띄운다. |
| F1-2 | 원본이 10MB를 넘으면 거부한다. 전송 전 브라우저에서 긴 변 1024px JPEG로 줄여 전송량을 줄인다. |
| F1-3 | 서버 `POST /api/recognize`가 `{ image: dataURL }`을 받아 이미지 모델을 호출한다. |
| F1-4 | 모델에게 JSON만 답하도록 요청하고, 응답에서 JSON을 추출해 `{ name, quantity, category }` 배열로 정규화한다. |
| F1-5 | 분류는 `채소·과일·육류·해산물·유제품·달걀·가공식품·소스/양념·기타` 중 하나로 맞춘다. |
| F1-6 | 재료를 하나도 찾지 못하면 "재료를 찾지 못했어요"를 안내한다. |

## API 키 / 데모 모드
- 키는 서버만 `.env`의 `OPENROUTER_API_KEY`에서 읽는다. 브라우저에는 절대 내려보내지 않는다.
- `.env.example`에 키 넣는 법을 적고, `.env`는 `.gitignore`에 넣는다.
- 키가 없거나 예시값 그대로면 앱이 멈추지 않고 **데모 모드**로 실행된다.
  - 화면 맨 위에 데모 띠를 표시한다(`GET /api/status`의 `demo` 값 기준). 문구는 `demoReason`으로 나눈다: `'no-key'`면 "데모 모드: API 키 없음"(키 넣는 법 안내), `'forced'`면 "데모 모드: 직접 켬"(`--demo`/`DEMO_MODE=1` 없이 다시 켜라는 안내).
  - `/api/recognize`는 API를 호출하지 않고 샘플 재료 목록을 돌려준다.
- `DEMO_MODE=1` 환경 변수 또는 `--demo` 옵션으로 키가 있어도 데모 모드를 강제할 수 있다(테스트용). 강제했으면 키 유무와 상관없이 `demoReason`은 `'forced'`다.

## 오류 처리
- API 오류(401·429·5xx·시간 초과 60초)는 사용자에게 한국어 메시지로 알리고 다시 시도할 수 있게 한다. 오류 문구는 [재료 인식하기] 버튼 바로 옆 상태 칸에 남겨 둔다(파일 형식·크기 오류도 같은 자리).
- 키가 있는데 API 호출이 실패하면 데모 데이터로 몰래 대체하지 않는다(실패를 그대로 알림).

## 완료 기준
- 데모 모드에서 사진 업로드 → 샘플 재료 목록이 표시되고 상단에 데모 띠가 보인다.
- 키가 있으면 실제 모델 응답으로 재료 목록이 표시된다.
