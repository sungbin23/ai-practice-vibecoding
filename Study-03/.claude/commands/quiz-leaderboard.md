# 퀴즈 순위 시스템 관리

게임 안 🏆 리더보드의 **순위 규칙을 확인·검증·변경**합니다. 순위 계산은 `quiz-records.js`의 `getLeaderboard`(`startOfToday`, `startOfWeek`, `LEADERBOARD_SIZE`), 화면은 `quiz-ui.js`의 `renderLeaderboard`에 있습니다.

입력값: `$ARGUMENTS`. 첫 단어가 하위 명령입니다.

| 하위 명령 | 하는 일 | 파일 수정 |
|---|---|---|
| `rules` (기본값) | 현재 순위 규칙을 코드에서 읽어 설명 | 없음 |
| `show <JSON 경로…> [daily\|weekly\|all\|category:<카테고리>]` | 내보낸 기록 파일로 실제 순위표 계산 | 없음 |
| `verify` | 순위 규칙 자동 테스트 | 없음 |
| `change <변경 내용>` | 순위 규칙 변경 | 있음 |

- 사용 예:
  - `/quiz-leaderboard`
  - `/quiz-leaderboard show teacher/data/*.json weekly`
  - `/quiz-leaderboard show teacher/data/*.json category:과학`
  - `/quiz-leaderboard verify`
  - `/quiz-leaderboard change 동점이면 평균 응답 시간이 짧은 사람을 위로`
- 알 수 없는 하위 명령이면 위 표를 보여 주고 끝냅니다.
- **선생님 모드와의 차이:** 게임 안 리더보드는 한 브라우저에 저장된 프로필끼리의 순위입니다. 여러 학생 비교와 상대평가 등급은 `/teacher-dashboard`가 담당합니다. 이 명령은 게임 안 순위 규칙만 다룹니다.

## rules
`getLeaderboard`를 읽고 다음을 표로 설명합니다. 코드에서 확인한 내용만 씁니다.
- **기간 필터:**
  - daily는 오늘 0시부터입니다.
  - weekly는 이번 주 월요일 0시부터입니다(로컬 시간).
  - category는 카테고리별 도전 기록만 셉니다.
- **집계:** 프로필별 최고 기록 1개만 셉니다.
- **정렬:** 점수 → 정답률 → 먼저 세운 기록 순입니다.
- **인원:** 상위 `LEADERBOARD_SIZE`명만 보여 줍니다.
- **이름 표시:** 프로필 이름을 바꾸면 최신 이름으로 표시합니다.
- **알려진 한계:** 모드마다 점수 체계가 달라도 daily·weekly·all에서 모드를 섞어 비교합니다.

## show `<JSON 경로…> [기간]`
- 파일 형식은 `{ exportedAt, profiles, records }` 또는 기록 배열입니다. 형식이 다른 파일은 건너뛰고 이유를 보고합니다.
- **계산 방법:** `node`의 `vm`에서 `quiz-records.js`를 실행합니다. 가짜 `localStorage`에 모든 파일의 기록과 프로필을 합쳐 넣고 `getLeaderboard`를 그대로 호출합니다. 게임 화면과 같은 결과가 나오게 하기 위해서입니다.
  - 여러 파일에서 `profileId`가 겹치면 `파일이름:profileId`로 바꿔 서로 다른 사람으로 처리합니다.
- **보고:** 순위, 아바타·이름, 점수, 모드·카테고리, 일시를 보여 줍니다. 결과는 저장하지 않습니다(학생 개인정보).

## verify
`node`의 `vm`과 가짜 `localStorage`로 `quiz-records.js`를 실행하고, `now`를 고정한 테스트 기록으로 검사합니다. 스크립트는 scratchpad에 둡니다.
1. **daily:** 어제 23:59 기록은 빠지고 오늘 00:00 기록은 들어갑니다.
2. **weekly:** 기준일이 수요일일 때 이번 주 월요일 00:00 기록은 들어가고 지난 일요일 23:59 기록은 빠집니다. 기준일이 **일요일**일 때도 그 주 월요일부터 셉니다(경계 오류 확인).
3. **category:** 카테고리별 도전 기록 중 그 카테고리 기록만 들어갑니다. 다른 모드 기록은 빠집니다.
4. **프로필별 최고 1개:** 한 프로필이 여러 번 플레이해도 1줄이고, 그 줄은 최고 점수입니다.
5. **동점 처리:** 점수가 같으면 정답률이 높은 쪽이 위입니다. 정답률도 같으면 먼저 세운 기록이 위입니다.
6. **상위 10명:** 프로필 12개가 있으면 10줄만 나옵니다.
7. **이름 갱신:** 프로필 이름을 바꾸면 순위표에 새 이름이 나옵니다.
8. **화면 렌더링:** jsdom으로 🏆 리더보드를 열고 탭 4개를 차례로 누릅니다.
   - 행 수와 1위 이름이 `getLeaderboard` 결과와 같은지 확인합니다.
   - 현재 프로필 행에 `is-me` 클래스가 있는지 확인합니다.
   - 이름에 `<b>` 같은 HTML을 넣어도 글자로만 표시되는지 확인합니다.

- 항목별 ✅/❌, 실패 시 기댓값과 실제값을 보고합니다. ❌가 있어도 코드는 고치지 않고 원인 후보만 제시합니다.

## change `<변경 내용>`
1. **영향 범위 설명:** 바꾸기 전에 무엇이 어떻게 달라지는지 설명합니다.
   - 예: "동점 기준 추가 → 기존 순위 중 X가 바뀔 수 있음"
   - 예: "모드별 분리 → 탭 구조 변경 필요"
   - 기존 기록과 호환되지 않는 변경(필드 추가 등)이면 예전 기록 처리 방법도 정합니다.
2. **코드 수정:** 순위 계산은 `getLeaderboard`에서만 바꾸고, 화면이 바뀌면 `renderLeaderboard`와 `index.html`을 함께 고칩니다.
3. **파일 규칙:** 수정한 파일의 첫 줄 날짜 주석을 `(수정됨)`과 현재 시각으로 바꿉니다.
4. **검증:** `node --check`와 위 `verify`를 다시 실행합니다. 바뀐 규칙에 맞게 테스트 기댓값도 고치고, 새 규칙을 검사하는 테스트를 하나 이상 추가합니다.
5. **문서:** README와 Study-03 `CLAUDE.md`의 리더보드 설명을 고칩니다.
6. 커밋하지 않고 변경 내용과 검증 결과를 보고합니다.
