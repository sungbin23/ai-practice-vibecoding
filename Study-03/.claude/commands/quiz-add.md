# 새 퀴즈 추가

`quiz-data.js`에 **입력한 카테고리와 난이도**로 새 문제를 1개 추가합니다. 기존 문제와 형식을 똑같이 맞추고, 교차 검증 가이드라인을 반드시 지킵니다.

입력값: `$ARGUMENTS`

## 1. 인자 확인
- 사용 예: `/quiz-add 과학 medium`, `/quiz-add 한국사 hard`
- **띄어쓰기가 있는 카테고리:** `예술과 문화`처럼 카테고리에 공백이 있을 수 있으므로, 위 입력값에서 **마지막 단어를 난이도로, 나머지를 카테고리로** 봅니다(예: `/quiz-add 예술과 문화 easy`).
- **카테고리:** `quiz-data.js`에 이미 있는 `category` 값 중 하나여야 합니다(현재: `한국사`, `과학`, `지리`, `예술과 문화`). 새 카테고리는 만들지 않습니다.
- **난이도:** `easy` / `medium` / `hard` 중 하나입니다. `쉬움`·`보통`·`어려움`은 각각 `easy`·`medium`·`hard`로 바꿔서 씁니다.
- 카테고리나 난이도가 없거나 잘못되면 문제를 만들지 않습니다. 쓸 수 있는 값과 사용 예를 보여 주고 끝냅니다.

## 2. 기존 문제 파악
`quiz-data.js`를 읽고 다음을 확인합니다.
- **새 id:** 현재 가장 큰 `id` + 1
- **중복 방지:** 같은 카테고리의 기존 문제 목록. 이미 있는 문제와 주제나 정답이 겹치지 않게 합니다(예: 임진왜란·이순신 문제가 이미 있으면 같은 사건을 다시 묻지 않음).
- **정답 위치:** 같은 카테고리의 정답 위치(`correctAnswer`) 분포. 새 문제의 정답은 가장 적게 쓰인 위치에 둡니다.
- **난이도 기준:** easy는 초·중등 교과 수준의 기본 상식, medium은 고등 교과나 교양 수준, hard는 세부 연도·인물·사건까지 알아야 하는 수준입니다.

## 3. 문제 작성 — 교차 검증 가이드라인 (루트 `CLAUDE.md`)
아래 4가지를 모두 만족해야 합니다. 하나라도 만족하지 못하면 다른 사실로 문제를 다시 만듭니다.
1. **정답이 하나뿐인가?** 오답 보기 3개는 분명히 틀린 것이어야 합니다. 해석에 따라 정답이 될 수 있는 보기는 넣지 않습니다. 다르게 해석될 여지가 있으면 문제에 조건을 적습니다(예: 면적 기준).
2. **최상급 표현에 기준이 있는가?** '가장', '최초', '최대' 같은 표현을 쓰면 측정 기준을 적습니다(예: "(전통적 측정 기준)", "해발 고도 기준").
3. **시간과 범위가 명확한가?** 바뀔 수 있는 정보는 시점을 적고(예: "2024년 기준"), 지리적·분류적 범위를 한정합니다(예: "태양계 행성 중").
4. **교차 검증했는가?** 문제와 해설에 쓴 사실(연도, 수치, 인물, 정답)은 **WebSearch로 서로 다른 출처 2곳 이상**에서 확인합니다. 논란이 있는 내용은 주류 학설을 따르고, 해설에 다른 주장이 있다는 점도 적습니다. 출처끼리 내용이 다르거나 확인하지 못한 사실은 쓰지 않습니다.

## 4. 형식 맞추기
`validate_quiz.py`가 정규식으로 파싱하므로 기존 형식을 정확히 지킵니다.
```js
    {
        id: 41,
        category: "과학",
        difficulty: "medium",
        question: "문제 문장?",
        options: ["보기1", "보기2", "보기3", "보기4"],
        correctAnswer: 2,
        explanation: "정답 이유와 근거가 되는 사실을 한두 문장으로 적습니다."
    },
```
- **값 쓰는 법:**
  - 문자열은 큰따옴표로 감싸고 한 줄에 씁니다. 문자열 안에 큰따옴표가 필요하면 작은따옴표(`'…'`)를 씁니다.
  - 보기는 꼭 4개이고, 길이와 형식을 비슷하게 맞춥니다.
  - `correctAnswer`는 정답 보기의 **0부터 시작하는 인덱스**입니다.
- **넣을 위치:**
  - 해당 카테고리 구역(`// --- 카테고리 ---` 주석 아래)의 마지막 문제 바로 뒤에 넣습니다. 객체를 닫는 `}`는 별도 줄에 둡니다.
  - 앞 객체 뒤의 쉼표를 확인합니다. 배열의 마지막 항목 뒤에는 쉼표를 붙이지 않습니다.
- **파일 머리 주석:**
  - 첫 줄 날짜 주석에 `(수정됨)`을 붙이고 현재 시각으로 바꿉니다. 시각은 `date "+%Y-%m-%d %H:%M"`로 확인합니다.
  - 둘째 줄의 문제 수 설명(예: "40문제")을 실제 문제 수에 맞게 고칩니다.

## 5. 검증과 보고
1. `python validate_quiz.py`를 실행합니다. 실패하면 원인을 고치고 다시 실행합니다.
2. 새 문제에 최상급 표현 경고가 나오면 2번 가이드라인을 다시 확인합니다.
3. 다음 내용을 보고합니다.
   - 추가한 문제 전체(코드 블록)와 정답 보기 번호(인덱스 + 1)
   - 가이드라인 4개 항목별 확인 결과(✅ 또는 조치 내용)
   - 교차 검증한 출처 2곳 이상(사이트 이름과 URL, 확인한 사실)
   - 카테고리별 문제 수 변화(예: 과학 10 → 11)
   - `validate_quiz.py` 결과 한 줄
4. 문제 수가 바뀌어 README의 문제 수 설명이 실제와 달라지면 함께 알려 줍니다. 수정은 하지 않습니다.
   - 전체 도전은 40문제, 카테고리별 도전은 10문제를 무작위로 뽑습니다(`quiz-game.js`의 `MODE_QUESTION_COUNT`). 그래서 문제를 추가해도 한 게임에서 푸는 문제 수는 그대로입니다.

커밋은 사용자가 요청할 때만 합니다.
