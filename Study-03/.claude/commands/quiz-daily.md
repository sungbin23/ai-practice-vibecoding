# 퀴즈 일일 점검·보충

`quiz-data.js`를 점검하고 부족한 부분에 새 문제를 추가한 뒤 백업하고 보고합니다. 아래 7단계를 **순서대로** 수행합니다.

입력값: `$ARGUMENTS`
- 추가할 문제 수입니다. 비어 있으면 **4**를 씁니다. 1~10 사이의 정수만 받습니다.
- 사용 예: `/quiz-daily`, `/quiz-daily 6`
- 정수가 아니거나 범위를 벗어나면 0단계에서 중단합니다.

## 공통 규칙: 단계별 검증과 즉시 중단
- 각 단계는 **작업 → 검증 → 결과 기록** 순서로 진행합니다. 다음 단계로 넘어가기 전에 그 단계의 "통과 조건"을 모두 확인합니다.
- 통과 조건을 하나라도 만족하지 못하면 **그 자리에서 중단**합니다. 다음 단계를 진행하지 않고, 이후 단계를 대신하는 작업이나 우회도 하지 않습니다.
- 중단하면 아래 형식으로 오류를 보고하고 끝냅니다.
  ```
  ❌ N단계(단계 이름)에서 중단
  - 실패한 조건:
  - 실제 값 / 오류 메시지:
  - 파일 변경 여부: 변경 없음 | 변경 후 원복함(원복 확인 결과)
  - 완료된 단계: 1~N-1
  - 권장 조치:
  ```
- **변경 후 실패 시 원복:** 5단계에서 `quiz-data.js`를 고친 뒤 실패하면 4단계 끝에 만든 임시 사본으로 파일을 되돌립니다. 되돌린 뒤 `python validate_quiz.py`가 통과하는지까지 확인하고 보고합니다.
- 커밋과 push는 하지 않습니다.

## 0단계. 사전 확인
- 작업: 입력값을 확인하고, `quiz-data.js`와 `validate_quiz.py`가 있는지 확인합니다. 시작 시각은 `date "+%Y-%m-%d %H:%M"`로 기록합니다.
- 통과 조건:
  - 추가할 문제 수가 1~10입니다.
  - 두 파일이 모두 있습니다.
  - 작업 전 `python validate_quiz.py`가 종료 코드 0입니다. 원래 데이터가 이미 깨져 있으면 문제를 추가하지 않습니다.

## 1단계. 파일 구조 이해
- 작업: `quiz-data.js` 전체를 읽고 다음을 정리합니다.
  - 머리 주석 형식(첫 줄 날짜, 둘째 줄 문제 수 설명)
  - 카테고리 구역 주석(`// --- 카테고리 ---`)의 순서
  - 객체 키 순서 `{ id, category, difficulty, question, options, correctAnswer, explanation }`
  - `correctAnswer`가 0부터 시작하는 인덱스라는 점
  - 큰따옴표 한 줄 문자열, 닫는 `}`가 별도 줄이라는 형식
- 같은 형식 규칙을 확인하려면 `validate_quiz.py`와 Study-03 `CLAUDE.md`도 읽습니다.
- 통과 조건:
  - 모든 객체가 위 7개 키를 같은 순서로 가집니다.
  - 카테고리 구역 주석이 카테고리마다 1개씩 있습니다.
  - 정리한 형식과 실제 파일이 다르면 중단합니다. 형식이 바뀐 파일에 추측으로 문제를 넣지 않기 위해서입니다.

## 2단계. 현재 문제 수와 분포 확인
- 작업: 다음을 표로 정리합니다.
  - 전체 문제 수, 가장 큰 `id`
  - 카테고리별 문제 수
  - 카테고리 × 난이도(easy/medium/hard) 문제 수
  - 카테고리 × 정답 위치(1~4번) 문제 수
- 숫자는 눈으로 세지 말고 스크립트로 셉니다. 예: `node -e`로 `quiz-data.js`를 실행해 `quizData`를 집계합니다.
- 통과 조건:
  - 스크립트 집계 결과가 `validate_quiz.py` 출력의 전체·카테고리별 문제 수와 같습니다.
  - `id`가 중복 없이 모두 정수입니다.

## 3단계. 카테고리별 부족한 부분 파악
- 작업: 카테고리마다 아래 기준으로 부족한 점을 찾고, 우선순위를 매겨 **이번에 추가할 문제의 카테고리·난이도·정답 위치 계획**을 세웁니다.
  1. **문제 수:** 다른 카테고리보다 적은 카테고리에 먼저 추가합니다. 수가 모두 같으면 카테고리마다 고르게 나눕니다.
  2. **난이도:** 카테고리 안에서 한 난이도가 50%를 넘거나, 비율이 20% 미만인 난이도가 있으면 그 난이도를 보충합니다.
  3. **정답 위치:** 카테고리 안에서 가장 적게 쓰인 정답 위치에 새 정답을 둡니다.
  4. **주제 공백:** 기존 문제가 다루지 않은 시대·분야를 적습니다(예: 한국사에서 근현대 문제가 적음).
- 통과 조건:
  - 계획한 문제 수가 입력한 개수와 같습니다.
  - 계획마다 카테고리, 난이도, 정답 위치, 다룰 주제, 그렇게 정한 근거가 있습니다.

## 4단계. 새 문제 추가 전 중복 체크
- 작업:
  - 계획대로 새 문제 초안을 작성합니다.
  - 루트 `CLAUDE.md`의 "퀴즈 문제 교차 검증 가이드라인" 4가지(정답 유일성, 최상급 기준, 시간·범위, 교차 검증)를 지킵니다.
  - 초안 속 사실(연도, 수치, 인물, 정답)은 **WebSearch로 서로 다른 출처 2곳 이상**에서 확인합니다. 확인하지 못한 사실은 쓰지 않고 다른 주제로 바꿉니다.
  - 초안마다 기존 문제 전체와 비교해 중복을 검사합니다.
    - **같은 문제:** `question` 문자열이 완전히 같으면 탈락입니다.
    - **같은 정답·주제:** 같은 카테고리에서 정답 보기가 같거나 같은 사건·인물·대상을 묻는 문제가 있으면 탈락입니다. 예를 들어 이순신 문제가 있으면 한산도 대첩도 다시 묻지 않습니다.
    - **해설과 겹침:** 기존 해설에 이미 답이 나와 있는 사실을 묻는 문제도 탈락입니다(예: id 4 해설의 "온조는 백제").
    - **새 문제끼리 중복:** 이번에 만든 새 문제끼리도 같은 기준으로 비교합니다.
  - 탈락한 초안은 주제를 바꿔 다시 만들고, 다시 검사합니다. 같은 자리에서 3번 연속 탈락하면 중단합니다.
  - 모두 통과하면 `quiz-data.js`의 **임시 사본**을 `backup/quiz-data.pre-<YYYYMMDD-HHMM>.js`로 만듭니다. 5단계에서 실패했을 때 되돌리기 위한 사본입니다.
- 통과 조건:
  - 모든 초안이 중복 검사와 가이드라인 4항목을 통과했습니다.
  - 초안마다 출처 2곳 이상이 기록되어 있습니다.
  - 임시 사본의 내용이 원본과 같습니다. `cmp` 등으로 확인합니다.

## 5단계. 문제 추가 후 형식 검증
- 작업:
  - 새 문제를 해당 카테고리 구역의 마지막 문제 뒤에 기존 형식 그대로 넣습니다.
  - `id`는 가장 큰 `id` + 1부터 차례로 붙입니다.
  - 머리 주석을 고칩니다. 첫 줄 날짜에 `(수정됨)`과 현재 시각을 넣고, 둘째 줄 문제 수 설명을 실제 문제 수로 바꿉니다.
- 검증:
  1. `python validate_quiz.py`의 종료 코드가 0입니다.
  2. 전체 문제 수가 "작업 전 문제 수 + 추가한 문제 수"와 같습니다.
  3. `node -e`로 파일을 실행했을 때 문법 오류가 없고 `quizData.length`가 2번의 값과 같습니다.
  4. 새 `id`가 연속되고 중복이 없습니다.
  5. 새 문제에서 최상급 표현 경고가 나오면 문장에 측정 기준이 있습니다.
  6. 기존 문제는 바뀌지 않았습니다. 임시 사본과 비교했을 때 차이가 머리 주석과 새 문제 추가분뿐이어야 합니다. `git diff --no-index` 등으로 확인합니다.
- 통과 조건: 위 6개를 모두 만족합니다. 하나라도 실패하면 임시 사본으로 원복하고 중단합니다.

## 6단계. 전체 데이터 백업
- 작업:
  - 검증을 통과한 `quiz-data.js`를 `backup/quiz-data-<YYYYMMDD-HHMM>.js`로 복사합니다.
  - `backup/` 폴더는 루트 `.gitignore`에 들어 있어 커밋되지 않습니다.
  - 백업 파일이 10개를 넘으면 오래된 것부터 지우지 말고, 개수만 보고에 적습니다.
- 통과 조건:
  - 백업 파일이 원본과 같습니다(`cmp` 종료 코드 0).
  - 백업 파일을 `python validate_quiz.py`와 같은 방식으로 집계했을 때 문제 수가 원본과 같습니다.
  - 4단계에서 만든 임시 사본은 지우지 않고 남겨 둡니다. 보고에 경로를 적습니다.

## 7단계. 실행 결과 상세 보고
아래 항목을 모두 보고합니다.
1. **요약:** 시작·종료 시각, 단계별 결과(1~6단계 각각 ✅와 검증 내용 한 줄)
2. **변경 전후 분포:** 카테고리별 문제 수, 카테고리 × 난이도, 카테고리 × 정답 위치. 변경 전과 후를 나란히 비교합니다.
3. **부족한 부분 분석:** 3단계에서 찾은 부족한 점과 이번에 보충한 내용, 아직 남은 부족한 점
4. **추가한 문제:** 문제마다 id, 카테고리, 난이도, 문제, 정답(보기 번호), 가이드라인 4항목 확인 결과, 교차 검증 출처(사이트 이름과 URL)
5. **중복 검사 기록:** 탈락한 초안과 탈락 이유(없으면 "없음")
6. **검증 결과:** `validate_quiz.py` 출력 요약과 5단계 검증 6항목 결과
7. **백업:** 백업 파일 경로, 임시 사본 경로, 현재 `backup/` 안의 백업 개수
8. **후속 확인:** README나 `CLAUDE.md`의 문제 수 설명이 실제와 달라졌으면 알려 줍니다. 수정은 하지 않습니다.
