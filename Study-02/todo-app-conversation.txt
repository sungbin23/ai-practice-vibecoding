● I created Study-02/CLAUDE.md. Following your memory rule, its first line is a
  date/time comment. It's written in Korean to match Study-01's CLAUDE.md.

  The project has no build, lint, tests or dependencies, so the file has no
  commands for those. It covers:

  - How to run: open index.html directly in a browser. To reset saved data, run
    localStorage.clear() in the browser console.
  - How script.js works:
    - Every change updates the global tasks array, saves it, then redraws the
      whole list with renderTasks().
    - Each task's click/edit/drag handlers must use originalIndex (its position
      in tasks). The list on screen is a filtered and sorted copy, so using the
      screen position changes the wrong task.
    - It records the task data shape, the three browser storage keys, and the
      export/import JSON format.
  - Adding a category: the three categories are hardcoded in all three files,
    and the file lists every place that needs changing.
  - Rules: the date/time comment rule and keeping UI text in Korean.

  I also found two things in the code worth knowing:
  - Drag-and-drop reordering doesn't show on screen. Dragging reorders the tasks
    array, but the list is always re-sorted with the selected sort option when
    it redraws.
  - README_old.md is a leftover copy. It's the same as README.md except for a
    missing final newline.

  The file isn't committed yet.

● I added keyword-based auto categorization. When you type a new task, the
  category dropdown changes automatically based on the words in it. In headless
  Chrome, 17 new tests and the 22 existing ones all pass, and a screenshot
  showed the hint on screen. Please try it in a real browser yourself too.

  How it works
  - Keyword lists: each category has its own list in script.js
    (CATEGORY_KEYWORDS):
    - Work: 회의, 보고서, 팀장, 계약, 마감 …
    - Personal: 운동, 병원, 장보기, 생일, 예약 …
    - Study: 시험, 과제, 토익, 코딩, 파이썬 …
  - While you type: the dropdown switches to the matching category with a brief
    highlight. A line below the input shows which keywords decided it, e.g. "🤖
    자동 분류: 공부 (키워드 '복습', '알고리즘', '기말고사')".
  - When keywords from two categories match: the category whose matched keywords
    are longer in total wins (longer words are treated as more specific). An
    exact tie, like "회의 끝나고 운동", or no match at all leaves the current
    choice unchanged.
  - Choosing a category yourself takes priority: if you change the dropdown,
    auto categorization pauses and the hint reads "✋ 직접 선택한 카테고리를
    사용합니다". It switches back on once you add the task or clear the input.
  - Editing an existing task: double-click editing follows the same rules, as
    long as you haven't touched the category dropdown during that edit.
  - Avoiding wrong matches: keywords are matched as parts of words, so I left
    out very short ones that hide inside other words. For example, "약" would
    also match "계약" (contract), so I used "약국" (pharmacy) instead.
