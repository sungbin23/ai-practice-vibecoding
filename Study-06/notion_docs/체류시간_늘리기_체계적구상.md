# 웹 포트폴리오 체류 시간 2배 — 체계적 구상

## 1단계. 출발점: 기준선과 방문자
- **기준선부터 잽니다.** 지금 수치를 모르면 2배가 되었는지 판단할 수 없습니다. GA4 같은 도구를 설치해 2~4주 동안 아래 수치를 모읍니다.
  - 평균 참여 시간
  - 스크롤 깊이
  - 세션당 페이지 수
- **방문자를 세 유형으로 나눕니다.**

| 유형 | 행동 | 관심사 |
|---|---|---|
| 채용 담당자 | 빠르게 훑어봄 | 요약, 경력 |
| 동료 개발자 | 깊이 읽음 | 코드, 기술 선택 이유 |
| 클라이언트 | 결과를 봄 | 성과, 신뢰 |

## 2단계. 원인 분해
**체류 시간 = 방문당 본 페이지 수 × 페이지당 머문 시간**

방문이 짧게 끝나는 원인을 세 가지로 나눕니다.

| 원인 | 증상 |
|---|---|
| (a) 첫 화면 이탈 | 로딩이 느림, 무엇을 하는 사람인지 바로 안 보임 |
| (b) 내용이 얕음 | 프로젝트가 스크린샷 몇 장뿐임 |
| (c) 막다른 페이지 | 다음에 볼 곳으로 가는 링크가 없음 |

한 가지 대책으로 2배를 만들기는 어렵습니다. 세 원인을 각각 개선해 효과를 **곱으로** 키웁니다.

## 3단계. 원인별 대책
- **(a) 첫 화면 이탈 줄이기**
  - LCP(가장 큰 요소가 보이는 시간)를 2.5초 이하로 줄입니다. 이미지는 WebP로 바꾸고 지연 로딩을 씁니다.
  - 첫 화면에 한 줄 소개, 대표 작업 하나, 눈에 띄는 행동 버튼을 둡니다.
  - 방문자 유형별 갈림길을 둡니다. 예: "1분 요약 보기" / "기술 상세 보기"
- **(b) 내용 깊게 만들기**
  - 프로젝트를 **사례 연구** 형식으로 다시 씁니다. 순서는 문제 → 과정 → 해결 → 결과이고, 결과에는 수치를 넣습니다.
  - 데모 영상이나 GIF, 라이브 데모 링크, 핵심 코드를 함께 보여 줍니다.
- **(c) 다음 볼거리로 이어 주기**
  - 글 끝에 "다음 프로젝트" 버튼과 관련 작업 카드를 둡니다.
  - 태그 필터를 두고, 개발 블로그로 연결합니다.

## 4단계. 수정: 체류 시간만 늘리면 안 됨 (3단계 재검토)
과한 애니메이션이나 억지 미니 게임은 체류 시간을 **부풀리기만** 하고, 바쁜 채용 담당자를 오히려 떠나게 할 수 있습니다. 체류 시간은 수단이고, 진짜 목표는 관심 있는 방문자가 더 깊이 보는 것입니다.

그래서 아래 **보조 지표**를 함께 봅니다.
- 스크롤 75% 도달률
- 프로젝트 상세 페이지 진입률
- 연락·이력서 클릭률

> 판정 기준: 체류 시간은 올랐는데 연락 클릭률이 떨어졌다면 **실패**로 봅니다.

## 5단계. 우선순위 (효과 대비 노력)

| 순위 | 할 일 | 노력 | 기대 효과 |
|---|---|---|---|
| 1 | 측정 도구 설치 + 로딩 속도 개선 | 적음 | 첫 화면 이탈 직접 감소 |
| 2 | 모든 페이지에 "다음 프로젝트"·관련 카드 | 적음 | 방문당 페이지 수 증가 |
| 3 | 대표 프로젝트 2~3개 사례 연구 재작성 + 데모 영상 | 중간 | 페이지당 시간 크게 증가 |
| 4 | 개발 블로그, 태그 필터 | 큼 | 장기적 재방문·탐색 증가 |
| 5 | 상호작용 연출 | 중간 | 소규모 A/B 시험으로만 검증 |

## 6단계. 실행·검증 일정

| 기간 | 할 일 | 중간 목표 (기준선 대비) |
|---|---|---|
| 0~2주 | 기준선 측정 | — |
| 3~4주 | 1·2순위 적용 | +30% |
| 5~8주 | 3순위 적용 | +70% |
| 9~12주 | 4순위 적용, A/B 시험 | **2배** |

- 단계마다 바꾼 뒤 2주씩 비교합니다.
- **위험 대응**
  - 방문자 수가 적으면 수치가 크게 흔들립니다. 주 단위 평균과 **중앙값**을 함께 봅니다.
  - 유입 경로(검색, SNS, 이력서 링크)별로 나눠 비교합니다.

## 결론
**측정 → 첫 화면 이탈 감소 → 내용 깊이 → 이어 보기** 순서로 고쳐 효과를 곱으로 쌓습니다. 연락 클릭 같은 보조 지표를 함께 지켜, 숫자만 늘고 실제 관심은 줄어드는 일을 막습니다.
